# 采集客户端：传输表示、双通道关联与收件确认

## 1. 双通道与最终回复

一次领取在两条 TCP 连接上完成，客户端把四个环节显式关联到同一次尝试：

1. 控制连接上的命令（`TYPE` / `REST` / `PASV` / `RETR`）；
2. `150` 初步回复，表示服务器愿意打开数据连接；
3. 数据连接上的字节流（原始接收事实）；
4. 控制连接上的**最终回复**（成功 `226`，失败 `4xx/5xx`）。

数据连接 `end`/`close` 只说明字节流结束，可能伴随的是 `451` 失败。
客户端在数据关闭后继续阻塞等待最终回复：拿不到 `226` 就抛 `FtpError`，
已收字节随 `error.partial` 带出并隔离留存。客户端内部命令串行，
晚到的最终失败归属于当前调用，不会被下一次领取吞掉。

## 2. 传输表示属于领取身份

`representation`（`A` 文本 / `I` 二进制）是领取身份的一部分，写入每份
收件确认与续传标记：

- **文本（TYPE A）**：CRLF 是网络表示事实，原样保存在 `staging/raw/`；
  规范内容把 CRLF 折回 LF 后再入目录。服务器 `SIZE` 是存储尺寸，
  与转换后本地字节数本来就不同，只作来源身份核对，不做长度断言。
- **二进制（TYPE I）**：无转换，规范内容等于接收字节，长度必须与
  领取后的 `SIZE` 一致；可选再核对 SHA-256。

## 3. 领取前后的身份核对

- 领取前：`SIZE` + `MDTM` 形成前置元数据；
- 领取后：再次读取并与前置比对。修改时间或尺寸变化（领取中被替换）
  即判定 `source-identity-changed`，本次内容隔离，不进目录。

## 4. 续传与重取

只有**二进制 + 身份绑定**的场景允许续传：

- 失败且已收部分字节时，把 `(文件名, 表示, mtime, 服务器尺寸, 已收字节数,
  隔离片段路径)` 写入 `state/*.marker.json`；
- 下一次领取先校验标记身份（表示、mtime、SIZE 全一致）再发 `REST 偏移`；
- 收到后半段后与隔离区历史片段**重组**，对完整字节做尺寸/摘要核对；
- 服务器拒绝 REST（`501/502/504`）时清除标记、整份重取，并在确认中说明；
- 标记身份过期（文件被替换）时整份重取。

文本表示经过换行转换，本地字节位置不能换算为服务器存储偏移：
**不发 REST、不写标记，一律整份重取**，确认中注明原因。

## 5. PASV 主机钉扎

`PASV` 回复中的六元组只取端口；数据主机必须命中配置的 `pinHosts`
（默认只允许控制连接所在主机）。回复指向未批准地址时直接拒绝连接，
防止控制回复把数据通道引到任意主机。

## 6. 落盘约定与收件确认

```
workspace/
  inbox/                  仅完整成功版本（原子 rename 进入）
  staging/raw/            每次尝试的原始网络字节
  staging/canon/          转换后的规范内容
  staging/quarantine/     失败尝试的原始字节（含续传历史片段）
  receipts/<attempt>.receipt.json   每份收件确认
  state/<name>.marker.json          身份绑定的续传标记
```

收件确认记录：尝试 ID、表示、续传决策、前后元数据、原始/规范字节数与
SHA-256、控制通道命令回复流水、核对说明、失败原因、入目录路径。
失败只产生隔离文件与确认，`inbox/` 永远只包含完整成功的版本。
